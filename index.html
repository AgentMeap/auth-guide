Tích hợp Firebase vào Flutter: đăng ký, đăng nhập, đăng nhập Google

Bạn tải về một project demo có sẵn giao diện, nhưng phần gọi Firebase được cố ý để trống. Làm theo trang này để dán từng đoạn code vào đúng chỗ, mỗi đoạn có giải thích code và dependency vừa dán. Kết thúc, app có đăng ký, đăng nhập, đăng nhập Google và lưu dữ liệu ở Firebase.

Tích vào ô vuông ở mỗi bước, thanh tiến độ ở trên cùng sẽ cập nhật. Có 15 chỗ dán, mỗi chỗ ghi nhãn PASTE-n.

Tổng quan

1. Bạn sẽ làm gì

Firebase cung cấp hai dịch vụ mà project này dùng, mỗi dịch vụ giữ một phần dữ liệu:

Dịch vụGiữ gìThư viện
Firebase AuthenticationEmail, mật khẩu (đã băm, app không thấy), tài khoản Google, phiên đăng nhập, email xác minh và đặt lại mật khẩufirebase_auth, google_sign_in

Các bước đi theo thứ tự: tải project (B0), chuẩn bị phía Firebase (B1, B2), dán code (B3), hiểu luồng (B4), chạy và kiểm tra (B5).

Cách app được tổ chức. Màn hình chỉ làm việc với AuthController; AuthController chỉ gọi FirebaseAuthService. Vì vậy toàn bộ code Firebase gom ở một file, và đó cũng là nơi bạn dán nhiều nhất.

B1. Cấu hình project Firebase

Không cần backend hay Docker. Bước này làm trên Firebase Console bởi người có quyền Owner hoặc Editor của project.

  1. Tạo project (hoặc dùng project có sẵn). Có thể tắt Google Analytics cho gọn.
  2. Authentication → Get started → Sign-in method: bật Email/Password và Google (chọn email hỗ trợ, bấm Save).
  3. Firestore Database → Create database: chọn chế độ production và một khu vực gần bạn.
  4. Firestore → tab Rules: xoá nội dung cũ, dán luật bên dưới rồi bấm Publish.
firestore.rules
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Mỗi người dùng chỉ đọc/ghi hồ sơ của chính mình.
    match /users/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;

      // Tự tạo hồ sơ: vai trò bắt buộc là CUSTOMER, email phải khớp tài khoản đăng nhập.
      allow create: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.role == 'CUSTOMER'
        && request.resource.data.email == request.auth.token.email.lower();

      // Được sửa tên, SĐT, ảnh; KHÔNG được đổi role hay email (chống tự phong ADMIN).
      allow update: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.role == resource.data.role
        && request.resource.data.email == resource.data.email;

      allow delete: if false;
    }

    // Mọi collection khác bị chặn.
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
Thiếu bước Publish này là lỗi phổ biến nhất. App sẽ báo "Firestore từ chối quyền truy cập" dù tài khoản đã xuất hiện trong Authentication. Luật trên cũng chặn người dùng tự đổi role thành ADMIN.

B2. Gắn ứng dụng Android vào Firebase

2.1. Package name phải khớp

Trong Firebase: Project settings → Your apps → Add app → Android. Ô Android package name phải bằng đúng applicationId trong android/app/build.gradle.kts của dự án bạn (dự án mẫu là vn.courtly.courtly).

Dự án của bạn có package khác? Không dùng được google-services.json của dự án mẫu. Hãy đăng ký app với package của bạn trong project Firebase của chính bạn rồi tải file của bạn.

2.2. Lấy SHA-1 của máy bạn và đăng ký

Google Sign-In kiểm tra dấu vân tay (SHA-1) của khoá ký app. Mỗi máy tính có một khoá debug riêng, nên mỗi người trong nhóm phải đăng ký SHA-1 của máy mình. Danh sách này nằm ở Project settings → Your apps → Android → SHA certificate fingerprints → Add fingerprint.

PowerShell
cd android
.\gradlew signingReport
bash
cd android
./gradlew signingReport

Tìm khối Variant: debug, lấy dòng SHA1: (dạng AA:BB:CC:...). Hoặc dùng keytool:

PowerShell
keytool -list -v -alias androiddebugkey -keystore "$env:USERPROFILE\.android\debug.keystore" -storepass android -keypass android
bash
keytool -list -v -alias androiddebugkey -keystore ~/.android/debug.keystore -storepass android -keypass android
Cả nhóm dùng chung một khoá? Có thể gửi file debug.keystore của một người cho cả nhóm chép vào thư mục .android, khi đó chỉ cần đăng ký một SHA-1. Chỉ làm vậy với khoá debug trong nhóm học tập, đừng đưa lên Git công khai.

2.3. Tải lại google-services.json

Sau khi thêm SHA-1, tải lại google-services.json từ cùng trang và đặt vào android/app/. Mở file kiểm tra: mỗi SHA-1 đã đăng ký tương ứng một mục "client_type": 1. Thiếu mục của bạn nghĩa là bạn tải file trước khi thêm SHA-1.

2.4. Lấy Web client ID

Google Sign-In trên Android cần Web client ID để trả về idToken. Lấy trong google-services.json, ở mục có "client_type": 3, trường client_id (dạng XXXX-xxxx.apps.googleusercontent.com). Hoặc ở Authentication → Sign-in method → Google → Web SDK configuration. Giữ giá trị này, bạn sẽ dán ở PASTE-7.

PASTE-8 Khôi phục phiên đăng nhập

File lib/services/firebase_auth_service.dart · hàm restore().

dán vào lib/services/firebase_auth_service.dart
    // Firebase tự lưu phiên đăng nhập trên máy. Lúc mở app, currentUser có thể
    // còn null vài trăm mili giây, nên đợi sự kiện đầu của authStateChanges
    // (tối đa 3 giây) rồi mới kết luận là chưa đăng nhập.
    final user =
        _auth.currentUser ??
        await _auth.authStateChanges().first.timeout(
          const Duration(seconds: 3),
          onTimeout: () => null,
        );
    if (user == null) return null;
    return _loadOrCreateProfile(user);
Giải thích code vừa dán
  • FirebaseAuth.instance.currentUser là người dùng hiện tại; Firebase giữ nó giữa các lần mở app nên không cần tự lưu token.
  • authStateChanges() là luồng báo mỗi khi trạng thái đăng nhập đổi.
  • Có người dùng thì đọc hồ sơ từ Firestore để biết tên và vai trò.

PASTE-11 Đăng nhập bằng Google

File lib/services/firebase_auth_service.dart · hàm signInWithGoogle().

dán vào lib/services/firebase_auth_service.dart
    try {
      if (googleServerClientId.startsWith('CHUA') ||
          googleServerClientId.startsWith('DÁN')) {
        throw const AuthException(
          'Chưa điền googleServerClientId (PASTE-7).',
        );
      }
      // 1. Khởi tạo Google Sign-In một lần, kèm Web client ID
      if (!_googleReady) {
        await GoogleSignIn.instance.initialize(
          serverClientId: googleServerClientId,
        );
        _googleReady = true;
      }
      // 2. Mở hộp chọn tài khoản Google
      final account = await GoogleSignIn.instance.authenticate();
      // 3. Lấy idToken của Google rồi đổi thành đăng nhập Firebase
      final idToken = account.authentication.idToken;
      if (idToken == null) {
        throw const AuthException('Không lấy được idToken từ Google.');
      }
      final credential = await _auth.signInWithCredential(
        fb.GoogleAuthProvider.credential(idToken: idToken),
      );
      // 4. Đọc hồ sơ; lần đầu đăng nhập thì tạo hồ sơ mới
      return _loadOrCreateProfile(credential.user!);
    } on GoogleSignInException catch (error) {
      throw AuthException(
        error.code == GoogleSignInExceptionCode.canceled
            ? 'Bạn đã huỷ đăng nhập Google. Nếu bạn không bấm huỷ, '
                  'hãy kiểm tra SHA-1 của máy đã thêm vào Firebase chưa.'
            : 'Đăng nhập Google thất bại (${error.code.name}).',
      );
    }
Giải thích code vừa dán
  • Luồng: Google cho idToken → đổi thành credential → signInWithCredential → Firebase tạo hoặc đăng nhập người dùng.
  • Báo "huỷ đăng nhập" dù không bấm huỷ nghĩa là SHA-1 của máy chưa đăng ký trong Firebase (xem mục B2).
  • Lần đầu một Gmail đăng nhập, _loadOrCreateProfile tự tạo hồ sơ trong Firestore với authProvider = GOOGLE.

Sửa lỗi

Xử lý lỗi thường gặp

Các lỗi dưới đây là lỗi nhóm đã gặp thật khi chạy dự án. Bấm vào từng mục để mở.

Thông báo "UnimplementedError: PASTE-n"

Bạn chưa dán chỗ số n (hoặc dán xong mà quên xoá dòng throw UnimplementedError(...) ngay dưới dòng TODO). Mở firebase_auth_service.dart, tìm PASTE-n và làm theo mục tương ứng ở B3.

Báo đỏ ở import của firebase_auth, cloud_firestore, google_sign_in

Chưa làm PASTE-1, hoặc đã dán nhưng chưa chạy flutter pub get. Nếu pub get báo lỗi về phiên bản (version solving) hay yêu cầu SDK mới hơn: chạy flutter upgrade, hoặc xoá 4 dòng đã dán và dùng lệnh flutter pub add firebase_core firebase_auth cloud_firestore google_sign_in để Flutter tự chọn phiên bản tương thích.

Build lỗi "google-services.json is missing" hoặc "No matching client found for package name"
  • Missing: chưa đặt google-services.json vào android/app/ (tải ở B2.3).
  • No matching client: package name trong Firebase khác applicationId của project. Mở android/app/build.gradle.kts xem applicationId, rồi đăng ký đúng tên đó trong Firebase (hoặc chạy lại flutter create --org ... với org khớp).
"Firebase chưa được khởi tạo" (no-app)

Chưa dán PASTE-5 và PASTE-6, hoặc dòng await Firebase.initializeApp(); nằm sau runApp. Nó phải nằm trong main(), sau WidgetsFlutterBinding.ensureInitialized() và trước runApp. Sau khi sửa phải chạy lại hẳn app (không dùng hot reload).

"Bạn đã huỷ đăng nhập Google" dù không bấm huỷ

Gần như luôn do SHA-1 của máy bạn chưa đăng ký trong Firebase. Khi không khớp, Google trả mã canceled và app dịch thành câu trên.

  1. Lấy SHA-1 máy bạn (mục B2.2) và nhờ người quản trị Firebase thêm vào đúng app Android.
  2. Tải lại google-services.json sau khi thêm. File mới có thêm một mục client_type: 1.
  3. Chạy flutter clean rồi flutter run.

Nếu SHA-1 đã đúng mà vẫn lỗi: kiểm tra điện thoại có tài khoản Google và Play Services mới, máy ảo là loại có Google Play, PASTE-7 là Web client ID (client_type 3) của đúng project, và Google đã bật trong Authentication.

"Chưa điền googleServerClientId"

Bạn chưa làm PASTE-7, hoặc dòng const vẫn là giá trị mẫu. Dán Web client ID thật (B2.4).

"Firestore từ chối quyền truy cập"

Luật bảo vệ Firestore chưa được áp dụng đúng. Dấu hiệu: tài khoản vẫn xuất hiện trong Authentication nhưng đăng ký hoặc đăng nhập báo lỗi.

  • Vào Firestore → Rules, đảm bảo nội dung là luật ở mục B1 và đã bấm Publish.
  • Luật mặc định allow read, write: if false;, hoặc luật "test mode" đã hết hạn, đều gây lỗi này.
  • Kiểm tra PASTE-14: role phải đúng 'CUSTOMER' và email là email viết thường của tài khoản, nếu không Rules sẽ từ chối.
  • Database phải có id (default), và bạn đang xem đúng project.

Tài khoản đã tạo dở dang sẽ tự có hồ sơ ở lần đăng nhập thành công kế tiếp sau khi sửa luật.

"Chưa bật đăng nhập Email/Password" hoặc "Chưa tạo Firestore Database"

Đó là hai việc ở mục B1. Vào Console bật Email/Password trong Authentication và tạo Firestore Database.

"Email này đã được đăng ký" khi tôi đăng ký lại để thử

Tài khoản từ lần thử trước vẫn còn. Dùng email khác, hoặc vào Console xoá user ở Authentication → Users và tài liệu cùng uid ở Firestore → users rồi đăng ký lại.

Email xác minh hoặc email đặt lại mật khẩu không về

Tìm trong mục Spam. Thư gửi từ địa chỉ dạng noreply@<project>.firebaseapp.com. Gửi liên tục nhiều lần sẽ bị chặn tạm thời (too-many-requests), chờ vài phút rồi thử lại.

Build lỗi "Gradle build daemon disappeared unexpectedly"

File android/hs_err_pid....log ghi "insufficient memory": máy hết RAM khi build. Thường do Docker (WSL2) hoặc nhiều ứng dụng nặng chạy cùng Android Studio.
