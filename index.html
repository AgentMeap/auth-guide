Môn PRM393FlutterCập nhật 06/10/2026

Tích hợp module bảo mật tài khoản vào dự án Flutter

Hướng dẫn từng bước để gắn đăng nhập, đăng ký có xác minh, quên mật khẩu và đăng nhập Google vào ứng dụng của bạn. Mã nguồn mẫu lấy từ dự án Courtly (ứng dụng đặt sân cầu lông) của nhóm.

Đường A · Spring Boot + SQL Server

Backend của nhóm: OTP 6 số gửi qua Gmail, JWT, refresh token, dữ liệu trong SQL Server.

Chọn khi: cần bảo mật kiểu "có server riêng", muốn demo OTP email.

Đường B · Firebase

Flutter nối thẳng Firebase Authentication và Firestore, không cần backend, không cần Docker.

Chọn khi: muốn làm nhanh, cần đăng nhập Google thật.

Dùng nút Cả hai / Spring Boot / Firebase ở thanh trên để chỉ xem đường bạn chọn. Tích vào ô vuông ở mỗi bước, thanh tiến độ ở trên cùng sẽ cập nhật.

Tổng quan

1. Module gồm những gì

Mọi màn hình chỉ làm việc với một lớp duy nhất là AuthManager. Lớp này giữ trạng thái đăng nhập và gọi một AuthService. Đổi AuthService thì đổi được nguồn xác thực mà không phải sửa giao diện.

Bước 3

Cấu hình Android

3.1. Cho phép truy cập mạng

Trong android/app/src/main/AndroidManifest.xml, phía trên thẻ <application>:

AndroidManifest.xml
<uses-permission android:name="android.permission.INTERNET"/>

3.2. Plugin Google Services (cho Firebase / Google Sign-In)

Hai file Gradle cần có plugin com.google.gms.google-services:

android/settings.gradle.kts
plugins {
    id("dev.flutter.flutter-plugin-loader") version "1.0.0"
    id("com.android.application") version "9.1.0" apply false
    id("org.jetbrains.kotlin.android") version "2.4.0" apply false
    id("com.google.gms.google-services") version "4.5.0" apply false
}
android/app/build.gradle.kts
plugins {
    id("com.android.application")
    id("com.google.gms.google-services")
    id("dev.flutter.flutter-gradle-plugin")
}

Giữ nguyên các phiên bản com.android.application và Kotlin mà dự án của bạn đang dùng. Chỉ thêm dòng của com.google.gms.google-services.

Cần file google-services.json. Khi đã bật plugin này, build sẽ lỗi nếu thiếu android/app/google-services.json. Đường Firebase sẽ có file thật ở bước B2. Nếu bạn chỉ đi đường Spring, hãy tạo một project Firebase trống để lấy file này, hoặc tạm bỏ dòng plugin ở cả hai file và chấp nhận không có Google thật.

3.3. Phiên bản Android tối thiểu

Firebase cần Android 6.0 (API 23) trở lên. Dự án Flutter mới đã đặt minSdk = flutter.minSdkVersion và thường đủ. Nếu build báo "minSdkVersion", đặt minSdk = 23 trong defaultConfig.

Bước 4

Chọn chế độ bằng --dart-define

Bạn không phải sửa code để đổi nguồn xác thực. app_config.dart đọc các giá trị lúc chạy:

lib/config/app_config.dart (trích)
enum AuthMode { mock, dummyJson, spring, firebase }

static const String _authModeName = String.fromEnvironment('AUTH_MODE');

static const AuthMode authMode = _authModeName == 'spring'
    ? AuthMode.spring
    : _authModeName == 'firebase'
    ? AuthMode.firebase
    : _authModeName == 'dummyjson'
    ? AuthMode.dummyJson
    : AuthMode.mock;
BiếnGiá trịÝ nghĩa
AUTH_MODE(bỏ trống) · spring · firebase · dummyjsonBỏ trống là chế độ mock: mọi thứ giả trong app, OTP luôn là 123456, không cần mạng.
GOOGLE_MODEfirebase · mock · offfirebase là Google thật (mặc định). mock hiện hộp chọn 3 tài khoản giả, chỉ dùng demo với AUTH_MODE=spring, và tự tắt ở bản release.
API_BASE_URLví dụ http://192.168.1.10:8080Địa chỉ backend, không có /api và dấu / cuối. Bỏ trống thì máy ảo Android dùng 10.0.2.2:8080.
Dễ nhầm. Nút ▶ (Run) của Android Studio không có tham số, nên app chạy ở chế độ mock. Muốn chạy chế độ khác, dùng lệnh flutter run --dart-define=... hoặc điền vào Run → Edit Configurations → Additional run args. Đổi --dart-define phải chạy lại hẳn, hot reload không áp dụng được.
Bước 5

Nối module vào main.dart

Có ba việc: khởi tạo Firebase (chỉ khi cần), khôi phục phiên đã lưu lúc mở app, và chọn màn hình theo trạng thái đăng nhập. Phiên bản rút gọn từ main.dart của Courtly:

lib/main.dart
import 'package:flutter/material.dart';

import 'screens/auth_screen.dart';
import 'screens/splash_screen.dart';
import 'services/auth_manager.dart';
import 'services/firebase_auth_service.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await initFirebaseIfEnabled(); // chỉ khởi tạo Firebase khi cần
  runApp(const MyApp());
}

class MyApp extends StatefulWidget {
  const MyApp({super.key});
  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {
  final _auth = AuthManager.instance;

  @override
  void initState() {
    super.initState();
    _auth.restoreSession(); // đọc phiên đã lưu, làm mới token, đồng bộ hồ sơ
  }

  @override
  Widget build(BuildContext context) {
    return ListenableBuilder(
      listenable: _auth,
      builder: (context, _) => MaterialApp(
        home: switch (_auth.status) {
          AuthStatus.unknown => const SplashScreen(),
          AuthStatus.unauthenticated => const AuthScreen(),
          AuthStatus.authenticated => HomeScreen( // màn chính của bạn
            user: _auth.currentUser!,
            onLogout: _auth.logout,
          ),
        },
      ),
    );
  }
}

HomeScreen là màn hình của riêng bạn. Dùng home: thay vì Navigator.push để người dùng không bấm Back quay lại màn đăng nhập khi đã vào trong.

Firebase chỉ khởi tạo khi cần. initFirebaseIfEnabled() bỏ qua việc khởi tạo khi không bật Google Sign-In và không ở chế độ firebase, và không bao giờ ném lỗi, nên thiếu google-services.json không làm app sập lúc mở.
Bước 6

Dùng AuthManager trong màn hình của bạn

Các màn AuthScreen, OtpVerifyScreen, ForgotPasswordScreen đã gọi sẵn AuthManager. Khi cần dùng ở chỗ khác:

dart
final auth = AuthManager.instance;

// Đăng nhập (identifier là email, hoặc số điện thoại ở chế độ spring)
final user = await auth.login('customer@courtly.vn', '123456');

// Đăng nhập Google (Google Sign-In thật, rồi Firebase)
await auth.loginWithGoogle();

// Đăng ký: chế độ spring cần OTP, chế độ firebase thì không
if (auth.requiresSignupOtp) {
  final sent = await auth.sendRegisterOtp(email);   // gửi OTP tới email
  // người dùng nhập mã, rồi:
  await auth.signup(SignupRequest(
    fullName: 'Nguyễn Văn A', email: email, phone: '0912345678',
    password: 'Abcdef1', otp: '123456',
  ));
} else {
  await auth.signup(SignupRequest(
    fullName: 'Nguyễn Văn A', email: email, password: 'Abcdef1',
  ));
}

// Thông tin hiện tại
auth.status;          // unknown | authenticated | unauthenticated
auth.currentUser;     // AppUser: id, fullName, email, phone, role
auth.isAdmin;         // true nếu role = ADMIN

await auth.logout();

Mọi lỗi được ném ra là AuthException có sẵn thông báo tiếng Việt trong message, bạn chỉ cần hiển thị:

dart
try {
  await AuthManager.instance.login(email, password);
} on AuthException catch (e) {
  ScaffoldMessenger.of(context)
      .showSnackBar(SnackBar(content: Text(e.message)));
}

Gọi API có đăng nhập (đường Spring)

ApiClient tự gắn Authorization: Bearer .... Gặp 401 thì refresh token một lần rồi gửi lại. Đường dẫn tính từ /api:

dart
final api = ApiClient();
final me = await api.getJson('/users/me');   // GET http://.../api/users/me
Đường Firebase. Không có ApiClient hay /api. Dữ liệu người dùng được đọc từ Firestore (users/{uid}) bên trong FirebaseDirectAuthService.

A1.4. Tuỳ chọn: Google giả để demo (không cần Firebase)

Trong .env thêm GOOGLE_MOCK_ENABLED=true rồi chạy docker compose up -d app. Ở Flutter dùng --dart-define=GOOGLE_MODE=mock, bấm nút Google sẽ hiện hộp chọn 3 tài khoản giả.

Chỉ dùng khi dev / demo. Với chế độ giả, ai cũng tự tạo được tài khoản cho một email chưa đăng ký. Backend từ chối khởi động nếu bật cùng profile prod hoặc cùng Firebase, và tài khoản giả không bao giờ đăng nhập được vào tài khoản có sẵn.

Muốn Google thật qua backend, xem hướng dẫn docs/FIREBASE_BACKEND_SETUP.md trong repo backend: đặt file service account tại ./secrets/service-account.json (đã được .gitignore và .dockerignore chặn) và đặt FIREBASE_ENABLED=true, FIREBASE_PROJECT_ID, FIREBASE_SERVICE_ACCOUNT_PATH=/run/secrets/firebase/service-account.json, GOOGLE_MOCK_ENABLED=false.

Đường A · Spring Boot

A2. Chạy Flutter nối với backend

Máy ảo Android (emulator)

Máy ảo tự gọi máy tính qua 10.0.2.2, bạn không cần API_BASE_URL:

terminal
flutter run --dart-define=AUTH_MODE=spring --dart-define=GOOGLE_MODE=mock

Điện thoại thật

Trên điện thoại, localhost và 10.0.2.2 đều sai. Có hai cách:

Cách 1: qua Wi-Fi. Điện thoại và máy tính cùng một Wi-Fi. Lấy IP máy tính:

PowerShell
ipconfig | Select-String "IPv4"
bash
ipconfig getifaddr en0      # macOS
hostname -I                  # Linux

B1. Cấu hình project Firebase

Không cần backend hay Docker. Bước này làm trên Firebase Console bởi người có quyền Owner hoặc Editor của project.

  1. Tạo project (hoặc dùng project có sẵn). Có thể tắt Google Analytics cho gọn.
  2. Authentication → Get started → Sign-in method: bật Email/Password và Google (chọn email hỗ trợ, bấm Save).
  3. Firestore Database → Create database: chọn chế độ production và một khu vực gần bạn.
  4. Firestore → tab Rules: xoá nội dung cũ, dán luật bên dưới rồi bấm Publish.
firestore.rules
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Mỗi người dùng chỉ đọc/ghi hồ sơ của chính mình.
    match /users/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;

      // Tự tạo hồ sơ: vai trò bắt buộc là CUSTOMER, email phải khớp tài khoản đăng nhập.
      allow create: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.role == 'CUSTOMER'
        && request.resource.data.email == request.auth.token.email.lower();

      // Được sửa tên, SĐT, ảnh; KHÔNG được đổi role hay email (chống tự phong ADMIN).
      allow update: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.role == resource.data.role
        && request.resource.data.email == resource.data.email;

      allow delete: if false;
    }

    // Mọi collection khác bị chặn.
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
Thiếu bước Publish này là lỗi phổ biến nhất. App sẽ báo "Firestore từ chối quyền truy cập" dù tài khoản đã xuất hiện trong Authentication. Luật trên cũng chặn người dùng tự đổi role thành ADMIN.

B2. Gắn ứng dụng Android vào Firebase

2.1. Package name phải khớp

Trong Firebase: Project settings → Your apps → Add app → Android. Ô Android package name phải bằng đúng applicationId trong android/app/build.gradle.kts của dự án bạn (dự án mẫu là vn.courtly.courtly).

Dự án của bạn có package khác? Không dùng được google-services.json của dự án mẫu. Hãy đăng ký app với package của bạn trong project Firebase của chính bạn rồi tải file của bạn.

2.2. Lấy SHA-1 của máy bạn và đăng ký

Google Sign-In kiểm tra dấu vân tay (SHA-1) của khoá ký app. Mỗi máy tính có một khoá debug riêng, nên mỗi người trong nhóm phải đăng ký SHA-1 của máy mình. Danh sách này nằm ở Project settings → Your apps → Android → SHA certificate fingerprints → Add fingerprint.

PowerShell
cd android
.\gradlew signingReport
bash
cd android
./gradlew signingReport

Tìm khối Variant: debug, lấy dòng SHA1: (dạng AA:BB:CC:...). Hoặc dùng keytool:

PowerShell
keytool -list -v -alias androiddebugkey -keystore "$env:USERPROFILE\.android\debug.keystore" -storepass android -keypass android
bash
keytool -list -v -alias androiddebugkey -keystore ~/.android/debug.keystore -storepass android -keypass android
Cả nhóm dùng chung một khoá? Có thể gửi file debug.keystore của một người cho cả nhóm chép vào thư mục .android, khi đó chỉ cần đăng ký một SHA-1. Chỉ làm vậy với khoá debug trong nhóm học tập, đừng đưa lên Git công khai.

2.3. Tải lại google-services.json

Sau khi thêm SHA-1, tải lại google-services.json từ cùng trang và đặt vào android/app/. Mở file kiểm tra: mỗi SHA-1 đã đăng ký tương ứng một mục "client_type": 1. Thiếu mục của bạn nghĩa là bạn tải file trước khi thêm SHA-1.

2.4. Điền Web client ID

Google Sign-In trên Android cần Web client ID để trả về idToken. Lấy trong google-services.json ở mục có "client_type": 3, hoặc ở Authentication → Sign-in method → Google → Web SDK configuration. Điền vào lib/config/app_config.dart (nếu dùng dự án mẫu thì điền vào hằng googleServerClientId ở đầu firebase_auth_service.dart, xem B2b):

lib/config/app_config.dart
static const String googleServerClientId =
    'XXXXXXXXXXXX-xxxxxxxx.apps.googleusercontent.com';

Bước 2. Tạo file lib/services/firebase_auth_service.dart

Tạo file mới với đúng tên và đường dẫn trên, dán toàn bộ nội dung sau. Đây là file duy nhất nói chuyện với Firebase.

lib/services/firebase_auth_service.dart
import 'package:cloud_firestore/cloud_firestore.dart';
import 'package:firebase_auth/firebase_auth.dart' as fb;
import 'package:google_sign_in/google_sign_in.dart';

import '../models/app_user.dart';
import 'auth_service.dart';

/// Web client ID dùng cho Google Sign-In trên Android.
/// Lấy trong android/app/google-services.json, mục có "client_type": 3
/// (hoặc Firebase Console > Authentication > Sign-in method > Google > Web SDK configuration).
const String googleServerClientId =
    'DÁN-WEB-CLIENT-ID-Ở-ĐÂY.apps.googleusercontent.com';

/// Xác thực bằng Firebase Authentication, hồ sơ lưu ở Firestore: users/{uid}.
class FirebaseAuthService implements AuthService {
  fb.FirebaseAuth get _auth => fb.FirebaseAuth.instance;
  FirebaseFirestore get _db => FirebaseFirestore.instance;

  static const _users = 'users';
  bool _googleReady = false;

  @override
  String get label => 'Firebase';

  // ---- Khôi phục phiên khi mở app -----------------------------------------

  @override
  Future<AppUser?> restore() => _guard(() async {
    final user = await _currentUser();
    if (user == null) return null;
    return _loadOrCreateProfile(user);
  });

  // ---- Email + mật khẩu ----------------------------------------------------

  @override
  Future<AppUser> login({required String email, required String password}) =>
      _guard(() async {
        final credential = await _auth.signInWithEmailAndPassword(
          email: email.trim(),
          password: password,
        );
        return _loadOrCreateProfile(_requireUser(credential));
      });

  @override
  Future<AppUser> signup({
    required String fullName,
    required String email,
    required String password,
    String? phone,
  }) => _guard(() async {
    final credential = await _auth.createUserWithEmailAndPassword(
      email: email.trim(),
      password: password,
    );
    final user = _requireUser(credential);
    final AppUser profile;
    try {
      await user.updateDisplayName(fullName.trim());
      profile = await _createProfile(user, fullName: fullName, phone: phone);
    } catch (_) {
      // Chưa có hồ sơ thì đăng xuất để không kẹt ở trạng thái nửa vời.
      // Lần đăng nhập sau sẽ tự tạo hồ sơ còn thiếu.
      await _auth.signOut();
      rethrow;
    }
    try {
      await user.sendEmailVerification(); // email chứa liên kết xác minh
    } catch (_) {
      // Gửi email xác minh là phần phụ, không làm hỏng đăng ký.
    }
    return profile;
  });

  /// Firebase gửi email chứa LIÊN KẾT đặt lại mật khẩu (không phải OTP 6 số).
  /// Trả về thành công kể cả khi email chưa đăng ký, nên không lộ email nào tồn tại.
  @override
  Future<void> sendPasswordReset(String email) =>
      _guard(() => _auth.sendPasswordResetEmail(email: email.trim()));

  // ---- Google --------------------------------------------------------------

  @override
  Future<AppUser> loginWithGoogle() => _guard(() async {
    try {
      await _ensureGoogleReady();
      final account = await GoogleSignIn.instance.authenticate();
      final idToken = account.authentication.idToken;
      if (idToken == null) {
        throw const AuthException(
          'Không lấy được idToken từ Google. Kiểm tra googleServerClientId.',
        );
      }
      final credential = await _auth.signInWithCredential(
        fb.GoogleAuthProvider.credential(idToken: idToken),
      );
      return _loadOrCreateProfile(_requireUser(credential));
    } on GoogleSignInException catch (error) {
      throw AuthException(
        error.code == GoogleSignInExceptionCode.canceled
            ? 'Bạn đã huỷ đăng nhập Google. Nếu bạn không bấm huỷ, '
                  'hãy kiểm tra SHA-1 của máy đã thêm vào Firebase chưa.'
            : 'Đăng nhập Google thất bại (${error.code.name}).',
      );
    }
  });

  // ---- Đăng xuất -----------------------------------------------------------

  @override
  Future<void> logout() async {
    try {
      await _auth.signOut();
      if (_googleReady) await GoogleSignIn.instance.signOut();
    } catch (_) {
      // Đăng xuất phía máy khách vẫn tiếp tục.
    }
  }

  // ---- Hỗ trợ --------------------------------------------------------------

  Future<void> _ensureGoogleReady() async {
    if (_googleReady) return;
    if (googleServerClientId.startsWith('DÁN')) {
      throw const AuthException(
        'Chưa điền googleServerClientId trong firebase_auth_service.dart (Bước 6).',
      );
    }
    await GoogleSignIn.instance.initialize(serverClientId: googleServerClientId);
    _googleReady = true;
  }

  fb.User _requireUser(fb.UserCredential credential) {
    final user = credential.user;
    if (user == null) {
      throw const AuthException('Firebase không trả về người dùng.');
    }
    return user;
  }

  /// Firebase khôi phục người dùng đã lưu bất đồng bộ lúc khởi động, nên có lúc
  /// currentUser còn null dù đã đăng nhập từ lần trước.
  Future<fb.User?> _currentUser() async {
    final current = _auth.currentUser;
    if (current != null) return current;
    return _auth.authStateChanges().first.timeout(
      const Duration(seconds: 3),
      onTimeout: () => null,
    );
  }

  Future<AppUser> _loadOrCreateProfile(fb.User user) async {
    final snapshot = await _db.collection(_users).doc(user.uid).get();
    if (snapshot.exists) return _fromData(user, snapshot.data() ?? const {});
    // Tài khoản Google lần đầu, hoặc đăng ký từng bị dở dang: tạo hồ sơ còn thiếu.
    return _createProfile(user, fullName: user.displayName, phone: null);
  }

  Future<AppUser> _createProfile(
    fb.User user, {
    required String? fullName,
    required String? phone,
  }) async {
    final email = (user.email ?? '').toLowerCase();
    final name = (fullName == null || fullName.trim().isEmpty)
        ? (email.contains('@') ? email.split('@').first : 'Người dùng')
        : fullName.trim();
    final provider = _providerOf(user);
    await _db.collection(_users).doc(user.uid).set({
      'fullName': name,
      'email': email,
      if (phone != null && phone.isNotEmpty) 'phone': phone,
      // Vai trò luôn là CUSTOMER khi tự tạo; Security Rules chặn giá trị khác.
      'role': 'CUSTOMER',
      'authProvider': provider,
      'createdAt': FieldValue.serverTimestamp(),
    });
    return AppUser(
      id: user.uid,
      fullName: name,
      email: email,
      phone: phone,
      authProvider: provider,
    );
  }

  AppUser _fromData(fb.User user, Map<String, dynamic> data) => AppUser(
    id: user.uid,
    fullName: (data['fullName'] as String?) ?? user.displayName ?? '',
    email: (data['email'] as String?) ?? user.email ?? '',
    phone: data['phone'] as String?,
    role: (data['role'] as String?) ?? 'CUSTOMER',
    authProvider: (data['authProvider'] as String?) ?? _providerOf(user),
  );

  String _providerOf(fb.User user) =>
      user.providerData.any((info) => info.providerId == 'google.com')
      ? 'GOOGLE'
      : 'LOCAL';

  /// Đổi mọi lỗi của Firebase thành AuthException có thông báo tiếng Việt.
  Future<T> _guard<T>(Future<T> Function() body) async {
    try {
      return await body();
    } on AuthException {
      rethrow;
    } on fb.FirebaseAuthException catch (error) {
      throw AuthException(_authMessage(error.code));
    } on FirebaseException catch (error) {
      throw AuthException(_firestoreMessage(error.code));
    }
  }

  String _authMessage(String code) => switch (code) {
    'invalid-credential' ||
    'invalid-login-credentials' ||
    'wrong-password' ||
    'user-not-found' => 'Email hoặc mật khẩu không đúng.',
    'invalid-email' => 'Email không hợp lệ.',
    'email-already-in-use' => 'Email này đã được đăng ký.',
    'weak-password' => 'Mật khẩu quá yếu (tối thiểu 6 ký tự).',
    'user-disabled' => 'Tài khoản đã bị khoá.',
    'too-many-requests' => 'Bạn thao tác quá nhanh, vui lòng thử lại sau.',
    'network-request-failed' => 'Không thể kết nối mạng.',
    'operation-not-allowed' =>
      'Chưa bật đăng nhập Email/Password trong Firebase Console.',
    _ => 'Firebase báo lỗi ($code).',
  };

  String _firestoreMessage(String code) => switch (code) {
    'no-app' =>
      'Firebase chưa được khởi tạo. Kiểm tra Bước 4 (Firebase.initializeApp) '
          'và file google-services.json.',
    'permission-denied' =>
      'Firestore từ chối quyền truy cập. Hãy dán và Publish firestore.rules.',
    'unavailable' || 'deadline-exceeded' => 'Không thể kết nối mạng.',
    'not-found' ||
    'failed-precondition' => 'Chưa tạo Firestore Database trong Firebase Console.',
    _ => 'Firestore báo lỗi ($code).',
  };
}

Sửa lỗi

Xử lý lỗi thường gặp

Các lỗi dưới đây là lỗi nhóm đã gặp thật khi chạy dự án. Bấm vào từng mục để mở.

"Không thể kết nối máy chủ" khi đăng nhập Spring

Nguyên nhân hay gặp: địa chỉ backend sai cho loại thiết bị đang dùng.

  • Máy ảo Android: dùng 10.0.2.2 (mặc định, không cần API_BASE_URL).
  • Điện thoại thật: 10.0.2.2 và localhost đều sai. Dùng IP LAN của máy tính (--dart-define=API_BASE_URL=http://IP:8080), hoặc adb reverse rồi dùng localhost.
  • Dùng IP ví dụ trong tài liệu (192.168.1.10, 192.168.1.13) mà không đổi sang IP máy bạn.
  • Máy tính có nhiều card mạng: chọn IP của card Wi-Fi, không chọn IP WSL/Docker (172.x).
  • Điện thoại và máy tính không cùng Wi-Fi, hoặc Wi-Fi chặn các thiết bị nhìn thấy nhau (Wi-Fi công cộng, trường học): dùng cáp USB với adb reverse.
  • Chưa dừng app và chạy lại sau khi đổi --dart-define.

Phép thử nhanh: mở http://IP-máy-tính:8080/swagger-ui.html bằng Chrome trên điện thoại. Không mở được thì là mạng hoặc firewall.

"Máy chủ phản hồi quá lâu" (timeout) Spring

App đã gửi yêu cầu nhưng không nhận được phản hồi. Khác với "không thể kết nối".

  • Firewall Windows bỏ gói tin: tạo luật cho phép cổng TCP 8080 (Windows Defender Firewall → Advanced settings → Inbound Rules → New Rule → Port → TCP 8080 → Allow).
  • Backend kẹt vì SQL Server chưa sẵn sàng: chạy docker compose ps và docker compose logs --tail=100 app. Tìm Login failed, Connection refused hoặc HikariPool ... timeout.
  • Backend vừa khởi động: chờ log hiện Started ... (có thể mất 30 đến 60 giây).
  • adb reverse đã mất hiệu lực: chạy lại lệnh.
"adb is not recognized" (không tìm thấy lệnh adb) Chung

adb nằm trong Android SDK nhưng chưa có trong PATH. Gọi bằng đường dẫn đầy đủ:

PowerShell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:8080 tcp:8080
bash
~/Library/Android/sdk/platform-tools/adb devices      # macOS
~/Android/Sdk/platform-tools/adb devices              # Linux

Lệnh devices phải liệt kê điện thoại với trạng thái device. Hiện unauthorized thì mở khoá điện thoại và bấm "Cho phép gỡ lỗi USB". SDK nằm chỗ khác thì xem Android Studio → Settings → Android SDK → Android SDK Location.

OTP không về, hoặc báo lỗi 503 / 429 Spring
  • 503: backend chưa cấu hình Gmail. Kiểm tra MAIL_USERNAME, MAIL_PASSWORD (App Password 16 ký tự viết liền, không phải mật khẩu Gmail) rồi docker compose up -d app.
  • 429: gửi quá nhanh (chờ 60 giây) hoặc quá 5 lần trong một giờ.
  • Không thấy thư: kiểm tra mục Spam. Thư gửi từ chính địa chỉ MAIL_USERNAME.
  • Chế độ mock (không có --dart-define) không gửi mail thật; OTP luôn là 123456.
Backend không khởi động Spring
  • Thiếu MSSQL_SA_PASSWORD hoặc JWT_SECRET trong .env: Docker Compose báo ngay khi chạy.
  • Mật khẩu SQL Server yếu: SQL Server từ chối. Dùng ≥ 8 ký tự, có chữ hoa, chữ thường, số và ký tự đặc biệt.
  • Bật cùng lúc FIREBASE_ENABLED=true và GOOGLE_MOCK_ENABLED=true: app từ chối khởi động. Chỉ bật một.
  • FIREBASE_ENABLED=true nhưng chưa có file ở ./secrets/service-account.json: app báo không đọc được file service account.
  • Xem lỗi cụ thể bằng docker compose logs --tail=100 app.
Số điện thoại bị từ chối Spring

Số điện thoại phải đúng 10 chữ số và bắt đầu bằng 0 (ví dụ 0912345678). Backend nhận 0 hoặc +84 cộng 9 số, Flutter chuẩn hoá về dạng 10 số trước khi gửi. Hai bên phải cùng quy tắc, nếu bạn đổi một bên thì đổi cả bên kia.

"Bạn đã huỷ đăng nhập Google" dù không bấm huỷ Firebase

Gần như luôn do SHA-1 của máy bạn chưa đăng ký trong Firebase. Khi không khớp, Google trả mã canceled và app dịch thành câu trên.

  1. Lấy SHA-1 máy bạn (mục B2.2) và nhờ người quản trị Firebase thêm vào đúng app Android.
  2. Tải lại google-services.json sau khi thêm. File mới có thêm một mục client_type: 1.
  3. Chạy flutter clean rồi flutter run --dart-define=AUTH_MODE=firebase.

Nếu SHA-1 đã đúng mà vẫn lỗi: kiểm tra điện thoại có tài khoản Google và Play Services mới, máy ảo là loại có Google Play, googleServerClientId là Web client ID của đúng project, và Google đã bật trong Authentication.

"Firestore từ chối quyền truy cập" Firebase

Luật bảo vệ Firestore chưa được áp dụng đúng. Dấu hiệu: tài khoản vẫn xuất hiện trong Authentication nhưng đăng ký hoặc đăng nhập báo lỗi.

  • Vào Firestore → Rules, đảm bảo nội dung là luật ở mục B1 và đã bấm Publish.
  • Luật mặc định allow read, write: if false;, hoặc luật "test mode" đã hết hạn, đều gây lỗi này.
  • Thử trong Rules Playground với thao tác get trên /users/<uid>, bật Authenticated.
  • Database phải có id (default), và bạn đang xem đúng project.

Tài khoản đã tạo dở dang sẽ tự có hồ sơ ở lần đăng nhập thành công kế tiếp sau khi sửa luật.

"Chưa bật đăng nhập Email/Password" hoặc "Chưa tạo Firestore Database" Firebase

Đó là hai việc ở mục B1. Vào Console bật Email/Password trong Authentication và tạo Firestore Database.

Build lỗi "Gradle build daemon disappeared unexpectedly" Chung

File android/hs_err_pid....log ghi "insufficient memory": máy hết RAM khi build. Thường do Docker (WSL2) và Android Studio cùng chiếm bộ nhớ.

PowerShell
docker compose down      # nếu đang chạy backend
wsl --shutdown
cd android
.\gradlew --stop
cd ..
flutter run --dart-define=AUTH_MODE=firebase

Đóng Chrome nhiều tab và các ứng dụng nặng. Dùng Docker thường xuyên thì giới hạn WSL bằng file %UserProfile%\.wslconfig ([wsl2] và memory=3GB), rồi chạy wsl --shutdown. File hs_err_pid*.log có thể xoá và không commit.

Cảnh báo "plugins that apply Kotlin Gradle Plugin (firebase_auth, firebase_core)" chỉ là cảnh báo, bỏ qua được.

Tôi chạy bằng nút ▶ nhưng vẫn ở chế độ mock Chung

Nút ▶ không truyền --dart-define. Mở Run → Edit Configurations, điền vào Additional run args, ví dụ --dart-define=AUTH_MODE=firebase, hoặc chạy bằng lệnh flutter run ... trong terminal. Đăng nhập thử bằng customer@courtly.vn: vào được thì app đang gọi backend, còn demo@courtly.vn vào được thì app đang ở mock.
